RejectionSamplers.AbstractGlobalTransformProposal — Type
AbstractGlobalTransformProposal{T} <: AbstractCoordinateProposal{T}

Abstract supertype for global transformation–based proposals.

This type represents proposals where samples are generated in two stages:

  1. Unit random generation: draw random numbers in a canonical space (e.g. uniform numbers in [0,1] or standard Gaussian samples).
  2. Global transformation: map these unit random numbers into the target coordinate space via a proposal-defined transformation.

Variate form

  • Always a subtype of AbstractCoordinateProposal{T} with variate form CoordinateVariate.
  • The element type T is typically an SVector{N,<:Real}, representing multi-coordinate phase-space points.

Required interface

Subtypes must implement:

_global_transform!(
    proposal::AbstractGlobalTransformProposal{T},
    unit_rnd_coords::AbstractVector{T},
) where T
  • _global_transform! takes unit_rnd_coords, a collection of unit random coordinates, and transforms them in place into physical coordinates according to the proposal.

Sampling

The default _rand! implementation for AbstractGlobalTransformProposal executes:

  1. _rand!(rng, dest) — fill dest with unit random coordinates.
  2. _global_transform!(proposal, dest) — apply the global transformation in place.
Note

On GPUs, unit random generation and transformation may or may not be fused into a single kernel. If they are not fused, benchmarking against a local-transform implementation is recommended.

RejectionSamplers.AbstractLocalTransformProposal — Type
AbstractLocalTransformProposal{T} <: AbstractCoordinateProposal{T}

Abstract supertype for local transformation–based proposals.

This type represents proposals where each coordinate vector is generated by applying a local transformation to independently drawn unit random numbers.

Variate form

  • Always a subtype of AbstractCoordinateProposal{T} with variate form CoordinateVariate.
  • The element type T is typically an SVector{N,<:Real}, representing multi-coordinate phase-space points.

Required interface

Subtypes must implement:

_local_transform(
    proposal::AbstractLocalTransformProposal{T},
    unit_rnd_coord::T
) where T
  • _local_transform maps a single unit random coordinate (of type T) into a transformed coordinate according to the proposal definition.

Sampling

The default _rand! implementation for AbstractLocalTransformProposal executes:

  1. Draws unit random coordinates with rand(rng, TT) for each element, where TT is an SVector{N,<:Real}.
  2. Applies _local_transform(proposal, unit_rnd_coord) independently for each sampled unit vector.

This means that the transformation is applied locally and independently for every coordinate tuple.

Note

This approach is straightforward but may be less efficient than the global transform approach on GPU backends, since random generation and transformation are not fused into a single kernel.

RejectionSamplers.AbstractProposal — Type
AbstractProposal{T, F <: ProposalVariateForm}

Abstract supertype for proposal distributions.

Parameters

  • T: Element type of generated samples.
    • T <: Real for univariate proposals.
    • T <: NTuple{N,<:Real} for coordinate variate proposals.
  • F: Variate form, either Distributions.Univariate or CoordinateVariate.

Variate form

Unlike in Distributions.jl, where both cases are considered univariate, we explicitly distinguish:

  • Univariate proposals (F == Distributions.Univariate, T <: Real).
  • Coordinate variate proposals (F == CoordinateVariate, T <: NTuple{N,<:Real}).

This distinction is important because our data layout stores multiple coordinates inside a single NTuple, which is natural in physics applications where phase-space points consist of coordinate tuples.

Required interface

Subtypes of AbstractProposal must implement:

degrees_of_freedom(proposal::AbstractProposal)::Int
_rand!(rng::AbstractRNG, proposal::AbstractProposal{T}, dest::AbstractVector{T}) where {T}

  • degrees_of_freedom returns the number of coordinates generated by the proposal:

    • For univariate proposals: always 1.
    • For coordinate variate proposals: equals the tuple length N.

  • _rand! generates random samples and writes them into dest.

Supported destination arrays

dest can be a Vector, CuVector, ROCArray, OneArray, or MtlArray.

Depending on the RNG type, random numbers are either generated directly on device or generated on CPU and copied to the device.

RejectionSamplers._local_transform — Function
_local_transform(
    proposal::AbstractLocalTransformProposal{T},
    unit_rnd_coord::T
) where T

Interface function for local transformations of unit random coordinates.

Arguments

  • proposal: an instance of a subtype of AbstractLocalTransformProposal.
  • unit_rnd_coord: a single unit random coordinate, typically an SVector{N,<:Real}, drawn from a canonical distribution (e.g. uniform in [0,1] or standard normal).

Returns

  • The transformed coordinate(s), of the same type as unit_rnd_coord, according to the transformation defined by proposal.

Description

Applies the local transformation for a single draw of unit random coordinates. This function is invoked repeatedly by _rand! to generate a full set of samples.

RejectionSamplers.filter_scan — Method
filter_scan(payload, weights, randoms, out_payload, out_weights, out_size)

KernelAbstractions kernel. Filters the payload array by comparing the respective elements of weights < randoms. Fills the indices out_size - out_size + N of the given buffers out_payload and out_weights with all accepted values, where N is the number of accepted values. Also assigns out_size += N.

Parameters

  • input payload: array of the payload
  • input weights: array of weights (normalized to [0,1]; outliers allowed, see out_weights; "probabilities")
  • input randoms: array of uniform random independent scalar values [0,1]
  • output out_payload: buffer for accepted payload to be written
  • output out_weights: buffer for accepted weights to be written; every accepted weight will be 1.0, or the original weight if it was larger than 1.0
  • input/output out_size: a global memory variable (array of length 1) containing the current number of elements in out_payload and out_weights
Warn

No inbounds checks are performed anywhere! Take care that payload, weights and randoms are all of the same length M, and that out_payload and out_weights have at least M+out_size length.

Warn

out_size must be set correctly (to the number of set elements in out_payload and out_weights) before calling the kernel. Also note that Int64 is not supported on some backends (Metal.jl and oneAPI.jl).
